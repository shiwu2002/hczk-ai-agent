# 运行时健康检查对接文档

> 本文档面向**平台开发者**，说明如何对接通用智能体运行时（demoAgent）的健康检查接口，实现平台对运行时状态的实时监控。

---

## 一、接口总览

运行时提供三级健康检查，无需认证，供平台和 K8s 探针使用：

| 方法 | 路径 | 用途 | 检查范围 |
|------|------|------|---------|
| `GET` | `/api/health/live` | 存活探针 | 仅进程存活，不检查依赖 |
| `GET` | `/api/health/ready` | 就绪探针 | MySQL + 知识库 + LLM 全部就绪 |
| `GET` | `/api/health` | 综合检查 | 各组件详细状态 + 运行时信息 |

**服务基础地址**: `http://<runtime-host>:3000`

---

## 二、存活探针（Liveness）

进程存活即返回 200，不检查任何外部依赖。适用于 K8s liveness probe，判断是否需要重启容器。

### 请求

```
GET /api/health/live
```

### 响应

```json
HTTP 200

{
  "status": "alive",
  "uptime": 3600000,
  "timestamp": 1718400000000
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | string | 固定值 `"alive"` |
| `uptime` | number | 进程运行时长（毫秒） |
| `timestamp` | number | 当前时间戳（毫秒） |

### K8s 配置示例

```yaml
livenessProbe:
  httpGet:
    path: /api/health/live
    port: 3000
  initialDelaySeconds: 10
  periodSeconds: 30
  failureThreshold: 3
```

---

## 三、就绪探针（Readiness）

检查所有关键依赖是否就绪，全部就绪返回 200，任一不可用返回 503。适用于 K8s readiness probe，判断是否可以将流量路由到该实例。

### 检查的组件

| 组件 | 检查方式 | 失败影响 |
|------|---------|---------|
| MySQL | 执行 `SELECT 1` | 对话历史无法读写，Skill/绑定数据不可用 |
| 知识库服务 | 调用 `/health/ready` | 知识检索不可用 |
| LLM 服务 | 调用 `models.list()` | 对话生成不可用 |

### 请求

```
GET /api/health/ready
```

### 响应（就绪）

```json
HTTP 200

{
  "status": "ready",
  "timestamp": 1718400000000,
  "components": {
    "database": "connected",
    "knowledge": "connected",
    "llm": "available"
  }
}
```

### 响应（未就绪）

```json
HTTP 503

{
  "status": "not_ready",
  "timestamp": 1718400000000,
  "components": {
    "database": "connected",
    "knowledge": "disconnected",
    "llm": "unavailable"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | string | `"ready"` 或 `"not_ready"` |
| `components.database` | string | `"connected"` / `"disconnected"` |
| `components.knowledge` | string | `"connected"` / `"disconnected"` |
| `components.llm` | string | `"available"` / `"unavailable"` |

### K8s 配置示例

```yaml
readinessProbe:
  httpGet:
    path: /api/health/ready
    port: 3000
  initialDelaySeconds: 15
  periodSeconds: 10
  failureThreshold: 3
```

## 四、综合健康检查（Full Health）

返回各组件详细状态和运行时信息，供平台管理后台展示运行时状态面板。

### 请求

```
GET /api/health
```

### 响应（全部正常）

```json
HTTP 200

{
  "status": "ok",
  "timestamp": 1718400000000,
  "uptime": 3600000,
  "version": "1.0.0",
  "components": {
    "database": {
      "status": "connected",
      "latencyMs": 3
    },
    "knowledge": {
      "status": "connected",
      "url": "http://localhost:3001",
      "agentId": "default_agent"
    },
    "llm": {
      "status": "available",
      "model": "qwen/qwen3.5-9b",
      "latencyMs": 120
    }
  },
  "runtime": {
    "skills": [
      { "id": "customer_service", "version": "1.0.0" }
    ],
    "bindings": [
      { "merchantId": "default", "skillId": "customer_service", "enabled": true }
    ],
    "skillsCount": 1,
    "bindingsCount": 1
  }
}
```

### 响应（部分降级）

```json
HTTP 200

{
  "status": "degraded",
  "timestamp": 1718400000000,
  "uptime": 3600000,
  "version": "1.0.0",
  "components": {
    "database": {
      "status": "connected",
      "latencyMs": 3
    },
    "knowledge": {
      "status": "disconnected",
      "url": "http://localhost:3001",
      "agentId": "default_agent"
    },
    "llm": {
      "status": "unavailable",
      "model": "qwen/qwen3.5-9b",
      "error": "Connection refused"
    }
  },
  "runtime": {
    "skills": [],
    "bindings": [],
    "skillsCount": 0,
    "bindingsCount": 0
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `status` | string | `"ok"` 全部正常 / `"degraded"` 部分降级 |
| `uptime` | number | 进程运行时长（毫秒） |
| `version` | string | 运行时版本号 |
| `components.database.status` | string | `"connected"` / `"disconnected"` |
| `components.database.latencyMs` | number | MySQL 查询延迟（毫秒），仅连接正常时返回 |
| `components.database.error` | string | 错误信息，仅连接异常时返回 |
| `components.knowledge.status` | string | `"connected"` / `"disconnected"` |
| `components.knowledge.url` | string | 知识库服务地址 |
| `components.knowledge.agentId` | string | 当前使用的智能体 ID |
| `components.llm.status` | string | `"available"` / `"unavailable"` |
| `components.llm.model` | string | 当前使用的 LLM 模型名 |
| `components.llm.latencyMs` | number | LLM 健康检查延迟（毫秒），仅可用时返回 |
| `components.llm.error` | string | 错误信息，仅不可用时返回 |
| `runtime.skills` | array | 已注册的 Skill 列表 |
| `runtime.bindings` | array | 商家绑定列表 |
| `runtime.skillsCount` | number | Skill 总数 |
| `runtime.bindingsCount` | number | 绑定总数 |

## 五、平台对接方式

### 5.1 定时轮询（推荐）

平台后端定时调用 `/api/health`，将结果写入监控面板或告警系统。

```python
import requests
import time

RUNTIME_URL = "http://runtime:3000"

def check_runtime_health():
    """定时检查运行时健康状态，建议每 30 秒调用一次"""
    try:
        resp = requests.get(f"{RUNTIME_URL}/api/health", timeout=5)
        data = resp.json()

        if data["status"] == "ok":
            print("✅ 运行时正常")
        elif data["status"] == "degraded":
            # 检查哪个组件异常
            for name, info in data["components"].items():
                status = info["status"] if isinstance(info, dict) else info
                if status in ("disconnected", "unavailable"):
                    print(f"⚠️ {name} 异常: {info}")

        return data
    except requests.RequestException as e:
        print(f"❌ 运行时不可达: {e}")
        return None

# 定时任务
while True:
    check_runtime_health()
    time.sleep(30)
```

### 5.2 网关前置检查

平台网关在转发用户请求前，可先调用 `/api/health/ready` 判断运行时是否就绪：

```python
@app.route('/api/v1/chat', methods=['POST'])
def chat():
    # 前置健康检查（可选，建议加超时和缓存避免每次都查）
    ready = check_ready_cache()
    if not ready:
        return {"error": "智能体服务暂时不可用，请稍后重试"}, 503

    # 正常路由逻辑
    ...
```

### 5.3 状态判断逻辑

| `status` 值 | 含义 | 平台处理建议 |
|-------------|------|-------------|
| `ok` | 全部组件正常 | 正常路由流量 |
| `degraded` | 部分组件异常 | 根据降级组件决定：知识库断开可降级为纯对话；LLM 断开则不可服务 |
| `not_ready` | 关键组件未就绪 | 停止路由流量，返回 503 |

### 5.4 告警规则建议

| 场景 | 检测方式 | 告警级别 |
|------|---------|---------|
| 运行时进程不可达 | `/api/health/live` 连续 3 次超时 | 严重 |
| MySQL 断开 | `/api/health` 中 `database.status = disconnected` | 严重 |
| LLM 不可用 | `/api/health` 中 `llm.status = unavailable` | 严重 |
| 知识库断开 | `/api/health` 中 `knowledge.status = disconnected` | 警告 |
| 组件延迟升高 | `latencyMs > 1000` | 警告 |
| Skill/绑定数为 0 | `runtime.skillsCount = 0` | 警告 |

## 六、快速验证

```bash

curl http://localhost:3000/api/health/live

# 2. 就绪检查

# 3. 综合检查（格式化输出）
curl -s http://localhost:3000/api/health | python3 -m json.tool
```
