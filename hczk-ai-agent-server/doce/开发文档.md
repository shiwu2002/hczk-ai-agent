# 桓宸智科AI平台 - 开发文档

## 一、项目概述

桓宸智科AI平台是一个面向企业与个人的AI智能体管理与计费系统，支持接入国内主流大模型（DeepSeek、文心一言、通义千问、智谱AI等），提供OpenAI兼容格式的API调用，同时支持美团、抖音等第三方平台智能客服对接。

### 核心功能
- **管理员端**：模型接入管理、智能体管理、API Key分配、用户管理、Token计费管理、平台对接配置
- **用户端**：智能体使用、用量统计、API Key管理、充值中心、账单查询
- **平台对接**：美团智能客服、抖音智能客服Webhook接入

## 五、计费规则

### 5.1 Token 计费流程

```
用户发送消息（JWT 或 API Key 认证）
    ↓
ChatService.streamChat()
    ↓ 1. 估算输入 tokens（系统提示词 + 用户消息）
    ↓ 2. 调用模型，流式输出，累积输出内容
    ↓
流式完成 → processBilling()
    ↓ 1. 估算输出 tokens
    ↓ 2. 计算费用 = 输入tokens × inputPrice/1000 + 输出tokens × outputPrice/1000
    ↓ 3. 获取用户 ID（API Key 认证从 details 取，JWT 认证从 username 查库）
    ↓ 4. BillingService.deductBalance() 扣减余额 + 写入 billing_records
    ↓ 5. 更新智能体统计（totalCalls +1, totalTokens 累加）
```

### 5.2 Token 估算规则

由于流式响应（SSE）无法从模型 API 获取精确的 usage 数据，系统采用字符数估算：

| 文本类型 | 估算比率 |
|----------|----------|
| 中文为主文本 | 约 1.5 字符 = 1 token |
| 英文/数字文本 | 约 4 字符 = 1 token |
| **综合混合文本** | **约 2 字符 = 1 token**（默认） |

估算工具类：`com.hczk.hczkaiagentserver.util.TokenCounter`

### 5.3 Token计费公式
```
费用 = input_tokens / 1000 × input_price + output_tokens / 1000 × output_price
```

- `input_price`：模型输入价格（元/千Tokens），存储在 `ai_models.input_price`
- `output_price`：模型输出价格（元/千Tokens），存储在 `ai_models.output_price`
- 费用精确到小数点后 6 位，四舍五入

### 5.4 计费示例

假设模型定价：输入 0.002 元/千Tokens，输出 0.002 元/千Tokens

| 场景 | 输入 | 输出 | 输入Tokens | 输出Tokens | 费用 |
|------|------|------|-----------|-----------|------|
| 短对话 | 100字 | 500字 | ~50 | ~250 | ¥0.0006 |
| 中等对话 | 500字 | 2000字 | ~250 | ~1000 | ¥0.0025 |
| 长对话 | 2000字 | 5000字 | ~1000 | ~2500 | ¥0.0070 |

### 5.5 模型价格示例
| 模型 | 输入价格 | 输出价格 |
|------|----------|----------|
| DeepSeek-V3 | ¥0.001/1K | ¥0.002/1K |
| ERNIE-4.0-Turbo | ¥0.008/1K | ¥0.008/1K |
| qwen-max | ¥0.02/1K | ¥0.02/1K |
| GLM-4-Plus | ¥0.01/1K | ¥0.01/1K |
| qwen-plus（百炼） | ¥0.004/1K | ¥0.012/1K |

### 5.6 余额不足处理

- 余额不足时，`BillingService.deductBalance()` 返回 `false`
- 系统记录警告日志，**不会中断已完成的对话**
- 用户需充值后才能继续调用

## 六、高并发与稳定性设计

### 6.1 Tomcat连接池配置
```yaml
server:
  tomcat:
    threads:
      max: 200
      min-spare: 20
    max-connections: 10000
    accept-count: 200
```

### 6.2 数据库连接池（HikariCP）
```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 50
      minimum-idle: 10
      connection-timeout: 30000
      idle-timeout: 600000
      max-lifetime: 1800000
```

### 6.3 Redis连接池
```yaml
spring:
  redis:
    lettuce:
      pool:
        max-active: 50
        max-idle: 20
        min-idle: 5
```

### 6.4 100用户并发保障措施
1. **连接池优化**：Tomcat 200线程 + HikariCP 50连接
2. **Redis缓存**：热点数据缓存，减少数据库压力
3. **异步处理**：Webhook消息异步处理
4. **数据库索引**：关键查询字段加索引
5. **限流保护**：API调用限流，防止单用户耗尽资源
6. **健康检查**：内置Actuator健康端点（可扩展）

## 七、部署指南

### 7.1 环境要求
- JDK 17+
- Node.js 18+
- Maven 3.9+
- MySQL 8.0+（生产环境）
- Redis 7.x（可选，生产推荐）

### 7.2 后端部署
```bash
cd hczk-ai-agent-server
mvn clean package -DskipTests
java -jar target/hczk-ai-agent-server-0.0.1-SNAPSHOT.jar
```

### 7.3 前端部署
```bash
cd hczk-agent-web
npm install
npm run build
# 部署dist目录到Nginx/静态服务器
```

### 7.4 生产环境配置
修改 `application.yaml`：
```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/hczk_ai_platform?useSSL=false&serverTimezone=Asia/Shanghai
    driver-class-name: com.mysql.cj.jdbc.Driver
    username: your_username
    password: your_password
  jpa:
    hibernate:
      ddl-auto: update
    properties:
      hibernate:
        dialect: org.hibernate.dialect.MySQLDialect
```
