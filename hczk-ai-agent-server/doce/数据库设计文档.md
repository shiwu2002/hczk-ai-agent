# 桓宸智科AI平台 - 数据库设计文档

## 一、概述

本文档描述桓宸智科AI平台的数据库设计，包括表结构、字段定义、索引设计、外键关系及ER图说明。

**数据库类型**：MySQL 8.0（生产环境）/ H2（开发测试环境）
**字符集**：utf8mb4
**排序规则**：utf8mb4_unicode_ci
**存储引擎**：InnoDB

---

## 二、ER关系图

```
+------------+       +------------+       +------------+
|   users    |<1---->|<  agents   |>-----<| ai_models  |
+------------+       +------------+       +------------+
      | 1                  | 1                  ^
      |                    |                    |
      |                    | 1                  | N:M (via model_ids)
      |              +------------+             |
      |              |platform_   |             |
      |              |configs     |             |
      |              +------------+             |
      |                                         |
      | 1:1                                     |
      v                                         |
+------------+                                   |
|  api_keys  |>---------------------------------+
+------------+
      |
      | 1
      v
+------------+       +------------+
|  billing_  |>-----<| recharge_  |
|  records   |       |  records   |
+------------+       +------------+
```

### 关系说明
| 主表 | 从表 | 关系类型 | 关联字段 |
|------|------|----------|----------|
| users | agents | 1:N | users.id = agents.user_id |
| users | api_keys | **1:1** | users.id = api_keys.user_id（唯一约束） |
| users | billing_records | 1:N | users.id = billing_records.user_id |
| users | recharge_records | 1:N | users.id = recharge_records.user_id |
| ai_models | agents | 1:N | ai_models.id = agents.model_id |
| api_keys | ai_models | N:M | api_keys.model_ids → ai_models.id（JSON字段） |
| api_keys | billing_records | 1:N | api_keys.id = billing_records.api_key_id |
| agents | platform_configs | 1:1 | agents.id = platform_configs.agent_id |

## 三、表结构设计

### 3.1 users（用户表）

**表说明**：存储平台用户信息，包括管理员和普通用户

| 字段名 | 数据类型 | 长度/精度 | 是否为空 | 默认值 | 说明 |
|--------|----------|-----------|----------|--------|------|
| id | BIGINT | - | NOT NULL | AUTO_INCREMENT | 主键 |
| user_id | VARCHAR | 32 | NOT NULL | - | 用户唯一标识（U+16位随机串），全局唯一 |
| username | VARCHAR | 50 | NOT NULL | - | 用户名，唯一 |
| password | VARCHAR | 255 | NOT NULL | - | BCrypt加密后的密码 |
| email | VARCHAR | 100 | NOT NULL | - | 邮箱地址 |
| phone_number | VARCHAR | 20 | YES | NULL | 手机号 |
| company_name | VARCHAR | 100 | YES | NULL | 公司名称 |
| role | TINYINT | - | NOT NULL | 1 | 用户角色：0=管理员，1=普通用户 |
| balance | DECIMAL | 19,4 | NOT NULL | 0.0000 | 账户余额（元） |
| total_usage_tokens | BIGINT | - | NOT NULL | 0 | 累计消耗token数 |
| status | TINYINT | - | NOT NULL | 0 | 账户状态：0=正常，1=禁用 |
| deleted | TINYINT | - | NOT NULL | 0 | 逻辑删除：0=未删除，1=已删除 |
| created_at | DATETIME | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | - | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

**索引设计**：
```sql
PRIMARY KEY (id),
UNIQUE KEY uk_user_id (user_id),
UNIQUE KEY uk_username (username),
UNIQUE KEY uk_email (email),
KEY idx_role (role),
KEY idx_status (status),
KEY idx_created_at (created_at)
```

### 3.2 ai_models（AI模型表）

**表说明**：存储接入的大语言模型配置信息（定价已迁移至api_keys表的unit_price字段）

| 字段名 | 数据类型 | 长度/精度 | 是否为空 | 默认值 | 说明 |
|--------|----------|-----------|----------|--------|------|
| id | BIGINT | - | NOT NULL | AUTO_INCREMENT | 主键 |
| name | VARCHAR | 100 | NOT NULL | - | 模型显示名称 |
| provider | VARCHAR | 100 | NOT NULL | - | 提供商名称 |
| provider_type | VARCHAR | 50 | NOT NULL | 'OPENAI_COMPATIBLE' | 接口类型 |
| model_id | VARCHAR | 100 | NOT NULL | - | 模型调用ID |
| status | TINYINT | - | NOT NULL | 0 | 状态：0=启用，1=停用 |
| api_base | VARCHAR | 255 | YES | NULL | API基础地址 |
| api_key | VARCHAR | 512 | YES | NULL | 平台API密钥（加密存储） |
| max_tokens | INT | - | YES | NULL | 最大上下文长度 |
| thinking | BOOLEAN | - | NOT NULL | FALSE | 是否启用深度思考 |
| created_at | DATETIME | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | - | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

**索引设计**：
```sql

UNIQUE KEY uk_model_id (model_id),
KEY idx_status (status),

```

### 3.3 agents（智能体表）

**表说明**：存储用户创建的AI智能体配置

| 字段名 | 数据类型 | 长度/精度 | 是否为空 | 默认值 | 说明 |
|--------|----------|-----------|----------|--------|------|
| id | BIGINT | - | NOT NULL | AUTO_INCREMENT | 主键 |
| name | VARCHAR | 100 | NOT NULL | - | 智能体名称 |
| description | TEXT | - | YES | NULL | 智能体描述 |
| model_id | BIGINT | - | YES | NULL | 关联模型ID（MODEL类型必填） |
| user_id | BIGINT | - | NOT NULL | - | 所属用户ID（外键） |
| status | TINYINT | - | NOT NULL | 0 | 状态：0=启用，1=停用 |
| agent_type | VARCHAR | 50 | YES | 'MODEL' | 智能体类型：MODEL/SKILL/ENDPOINT |
| skill_id | VARCHAR | 100 | YES | NULL | Skill ID（SKILL类型必填） |
| endpoint | VARCHAR | 255 | YES | NULL | 外部地址（ENDPOINT类型必填） |
| endpoint_auth_header | VARCHAR | 255 | YES | NULL | 认证头 |
| total_calls | BIGINT | - | NOT NULL | 0 | 累计调用次数 |
| total_tokens | BIGINT | - | NOT NULL | 0 | 累计消耗token数 |
| avg_latency | INT | - | YES | NULL | 平均响应延迟(ms) |
| created_at | DATETIME | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | - | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

**索引设计**：
```sql
PRIMARY KEY (id),
KEY idx_user_id (user_id),
KEY idx_model_id (model_id),
KEY idx_status (status),
KEY idx_agent_type (agent_type),
CONSTRAINT fk_agent_model FOREIGN KEY (model_id) REFERENCES ai_models(id),
CONSTRAINT fk_agent_user FOREIGN KEY (user_id) REFERENCES users(id)
```

### 3.4 api_keys（API密钥表）

**表说明**：存储用户的API调用密钥，每个用户仅允许一个API Key

| 字段名 | 数据类型 | 长度/精度 | 是否为空 | 默认值 | 说明 |
|--------|----------|-----------|----------|--------|------|
| id | BIGINT | - | NOT NULL | AUTO_INCREMENT | 主键 |
| name | VARCHAR | 100 | NOT NULL | - | 密钥名称 |
| api_key | VARCHAR | 512 | NOT NULL | - | 密钥值，唯一 |
| user_id | BIGINT | - | NOT NULL | - | 所属用户ID（外键，唯一约束） |
| model_ids | JSON | - | YES | NULL | 绑定的大模型ID列表（一对多） |
| unit_price | DECIMAL | 19,6 | NOT NULL | 0.000000 | 统一Token单价（元/千Tokens） |
| total_calls | BIGINT | - | NOT NULL | 0 | 累计调用次数 |
| total_input_tokens | BIGINT | - | NOT NULL | 0 | 累计输入Token数 |
| total_output_tokens | BIGINT | - | NOT NULL | 0 | 累计输出Token数 |
| total_cost | DECIMAL | 19,6 | NOT NULL | 0.000000 | 累计消费金额（元） |
| status | TINYINT | - | NOT NULL | 0 | 状态：0=可用，1=禁用 |
| last_used_at | DATETIME | - | YES | NULL | 最后使用时间 |
| created_at | DATETIME | - | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |

**索引设计**：
```sql
PRIMARY KEY (id),
UNIQUE KEY uk_api_key (api_key),
UNIQUE KEY uk_user_id (user_id),

```

## 六、性能优化建议

### 6.1 索引优化
- `users` 表的 `user_id`、`username` 和 `email` 已建立唯一索引
- `api_keys` 表的 `api_key` 和 `user_id` 已建立唯一索引（高频查询）
- `billing_records` 表按 `user_id + created_at` 组合查询频繁，建议建立联合索引
- `agents` 表按 `user_id` 查询频繁，已建立普通索引

### 6.2 分表分库建议（未来扩展）
- `billing_records` 和 `chat_logs` 数据量增长快，建议按月分表
- `recharge_records` 可保留热数据（近1年），冷数据归档

### 6.3 缓存策略
- 用户余额信息缓存到Redis（5分钟过期），减少数据库查询
- 用户信息缓存到Redis（24小时过期）
- API Key映射关系缓存到Redis（24小时过期），提升鉴权效率
- Redis不可用时自动降级到数据库查询，不影响业务
