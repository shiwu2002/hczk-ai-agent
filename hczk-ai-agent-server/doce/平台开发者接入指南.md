# 通用智能体运行时 — 平台开发者接入指南

> 本文档面向**平台开发者**，说明如何将通用智能体运行时（demoAgent）接入你的管理平台。
> 包含：架构设计逻辑、数据表设计、完整调用流程、接口规范、接入步骤。

---

## 一、设计逻辑与整体架构

### 1.1 核心设计思想

**平台做统一入口，所有智能体（包括通用运行时）都是平台背后的一个 endpoint。**

```
传统方案：每个商家部署一个独立智能体容器 → 资源浪费、运维复杂
Skill 方案：一个通用运行时 + N 个 Skill 配置包 → 资源共享、秒级接入
混合方案：平台统一路由，标准需求走 Skill 模式，定制需求走独立 endpoint
```

**两种接入模式**：

| 模式 | 说明 | 适合场景 |
|------|------|---------|
| **Skill 模式** | 商家绑定一个 Skill 配置包，走通用运行时执行 | 标准客服、销售、FAQ 等通用场景 |
| **Endpoint 模式** | 商家绑定一个独立智能体地址，平台直接转发 | 完全定制化的智能体，无法用 Skill 配置表达 |

**一个商家只能绑定一种模式**，`skill_id` 和 `agent_endpoint` 二选一。

### 1.4 平台网关统一路由逻辑

```python
@app.route('/api/v1/chat', methods=['POST'])
def chat():
    merchant_id = request.json['merchant_id']
    message = request.json['message']

    # 1. 查商家绑定
    binding = db.query(
        "SELECT * FROM merchant_agent_binding WHERE merchant_id = ? AND enabled = 1",
        merchant_id
    )
    if not binding:
        return {"error": "商家未绑定智能体"}, 400

    # 2. 前置校验（余额、限流，对所有模式统一）
    if not check_balance(merchant_id):
        return {"error": "余额不足"}, 403
    if not check_rate_limit(merchant_id):
        return {"error": "请求过于频繁"}, 429

    # 3. 路由：根据绑定模式决定转发目标
    start_time = time.time()

    if binding['agent_endpoint']:
        # Endpoint 模式：直接转发到定制智能体
        response = http_post(binding['agent_endpoint'], json={
            "message": message,
            "merchant_id": merchant_id,
            "session_id": request.json.get('session_id', str(uuid4())),
        }, headers=parse_auth(binding['agent_auth_header']))
    else:
        # Skill 模式：转发到通用运行时
        response = http_post("http://agent-runtime:3000/api/chat", json={
            "message": message,
            "merchant_id": merchant_id,
            "session_id": request.json.get('session_id', str(uuid4())),
            "collection_name": request.json.get('collection_name'),
            "agent_id": request.json.get('agent_id'),
        })

    # 4. 后置处理（计费、计量、持久化，对所有模式统一）
    usage = response.json()
    duration_ms = int((time.time() - start_time) * 1000)

    record_usage(merchant_id, usage, duration_ms)
    deduct_balance(merchant_id, calculate_cost(merchant_id, usage))
    persist_messages(merchant_id, message, usage)

    return usage
```

### 1.5 商家专属知识库区分机制

通用运行时通过 **collectionName** 和 **agentId** 区分每个商家的知识库：

```
用户请求 { merchant_id: "merchant_001", message: "如何退货", agent_id: "agent_001", collection_name: "products" }
    │
    ▼
SkillDispatcher.resolve("merchant_001")
    │
    ▼ 查绑定 → 合并 override
ResolvedSkill.capabilities.collectionName = "merchant_001_products"
    │
    ▼
knowledge_retrieval 节点:
  retriever.retrieve(query, "merchant_001_products", topK, "agent_001")
```

**collectionName 三层优先级**：

| 优先级 | 来源 | 场景 |
|--------|------|------|
| 1（最高） | 请求参数 `collection_name` | 临时指定知识库 |
| 2 | Skill `capabilities.collectionName` | 绑定时通过 `capabilities_override` 指定 |
| 3（兜底） | 默认值 `'default'` | 公共知识库 |

**agentId 两层优先级**：

| 优先级 | 来源 | 场景 |
|--------|------|------|
| 1（最高） | 请求参数 `agent_id` | 每次调用指定智能体 ID |
| 2（兜底） | 配置文件 `knowledge.agentId` | 默认智能体 ID |

## 二、数据表设计（共 11 张）

### 2.1 你负责的表（11 张，全部在平台数据库）

```sql
-- ========================================
-- 1. merchant — 商家表
-- ========================================
CREATE TABLE merchant (
  id              VARCHAR(64)  PRIMARY KEY,
  name            VARCHAR(128) NOT NULL,
  industry        VARCHAR(64),
  contact_name    VARCHAR(64),
  contact_phone   VARCHAR(32),
  contact_email   VARCHAR(128),
  status          ENUM('active','suspended','deleted') DEFAULT 'active',
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- ========================================
-- 2. skill — 技能包注册表
-- 说明：此表同时存在于平台数据库和运行时本地 SQLite
--       平台侧用于计费/展示/审计，运行时侧用于实时调度
--       两者通过平台管理 API 同步
-- ========================================
CREATE TABLE skill (
  id              VARCHAR(64)  PRIMARY KEY,
  name            VARCHAR(128) NOT NULL,
  category        VARCHAR(32),                       -- customer_service / sales / faq / complaint / guide / custom
  version         VARCHAR(32)  DEFAULT '1.0.0',
  description     TEXT,

  -- 三层定义（JSON 格式）
  persona         JSON NOT NULL,                     -- Layer 1: 人设 { name, systemPrompt, tone, instructions }
  capabilities    JSON NOT NULL,                     -- Layer 2: 能力 { tools, knowledgeRetrieval, collectionName, maxToolIterations }
  workflow        JSON NOT NULL,                     -- Layer 3: 执行流程 DAG { entry, nodes[], edges[] }

  -- 运行时配置
  config          JSON NOT NULL,                     -- { maxIterations, toolTimeoutMs, toolMaxRetries, contextWindowSize, temperature }

  status          ENUM('active','inactive','draft') DEFAULT 'draft',
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- ========================================
-- 3. merchant_agent_binding — 商家智能体绑定（核心路由表）
-- 支持两种模式：
--   Skill 模式：skill_id 有值，agent_endpoint 为空 → 走通用运行时
--   Endpoint 模式：agent_endpoint 有值，skill_id 为空 → 走定制智能体
-- 两者二选一
-- ========================================
CREATE TABLE merchant_agent_binding (
  id                    BIGINT AUTO_INCREMENT PRIMARY KEY,
  merchant_id           VARCHAR(64)  NOT NULL,

  -- Skill 模式字段
  skill_id              VARCHAR(64),

  -- Endpoint 模式字段
  agent_endpoint        VARCHAR(256),
  agent_auth_header     VARCHAR(256),       -- 如 "Bearer sk-xxx"

  -- Skill 模式的覆盖配置（JSON，覆盖 Skill 默认值）
  persona_override      JSON,              -- 覆盖人设（如自定义系统提示词、名字）
  capabilities_override JSON,              -- 覆盖能力（如指定专属知识库 collectionName）
  config_override       JSON,              -- 覆盖配置（如指定模型温度）

  -- 商家专属工具配置（JSON）
  tools_config          JSON,              -- 工具的 endpoint / auth 等配置

  enabled               BOOLEAN DEFAULT TRUE,
  created_at            DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at            DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  UNIQUE KEY uk_merchant (merchant_id),
  FOREIGN KEY (merchant_id) REFERENCES merchant(id),
  FOREIGN KEY (skill_id) REFERENCES skill(id)
);

-- ========================================
-- 4. skill_pricing — 计费规则表
-- ========================================
CREATE TABLE skill_pricing (
  id                      BIGINT AUTO_INCREMENT PRIMARY KEY,
  skill_id                VARCHAR(64)  NOT NULL,
  billing_type            ENUM('per_call','per_token','per_session','monthly') NOT NULL,

  price_per_call          DECIMAL(10,4),
  price_per_input_token   DECIMAL(10,6),
  price_per_output_token  DECIMAL(10,6),
  price_per_session       DECIMAL(10,4),
  monthly_price           DECIMAL(10,2),
  monthly_included_calls  INT,
  free_calls_per_month    INT DEFAULT 0,

  effective_from          DATETIME NOT NULL,
  effective_to            DATETIME,
  created_at              DATETIME DEFAULT CURRENT_TIMESTAMP,

  FOREIGN KEY (skill_id) REFERENCES skill(id)
);

-- ========================================
-- 5. skill_usage — 调用计量表
-- ========================================
CREATE TABLE skill_usage (
  id                BIGINT AUTO_INCREMENT PRIMARY KEY,
  skill_id          VARCHAR(64),
  merchant_id       VARCHAR(64)  NOT NULL,
  user_id           VARCHAR(64),
  session_id        VARCHAR(64),

  call_type         ENUM('chat','stream','tool','knowledge') NOT NULL,

  input_tokens      INT DEFAULT 0,
  output_tokens     INT DEFAULT 0,
  tool_calls_count  INT DEFAULT 0,
  retrieval_count   INT DEFAULT 0,

  billing_type      VARCHAR(32),
  cost              DECIMAL(10,4) DEFAULT 0,

  duration_ms       INT,
  status            ENUM('success','error','timeout') NOT NULL,
  error_message     TEXT,

  called_at         DATETIME NOT NULL,
  created_at        DATETIME DEFAULT CURRENT_TIMESTAMP,

  INDEX idx_skill_called (skill_id, called_at),
  INDEX idx_merchant_called (merchant_id, called_at)
);

-- ========================================
-- 6. merchant_balance — 商家余额表
-- ========================================
CREATE TABLE merchant_balance (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  merchant_id     VARCHAR(64)  NOT NULL,
  balance         DECIMAL(12,4) NOT NULL DEFAULT 0,
  frozen_balance  DECIMAL(12,4) NOT NULL DEFAULT 0,
  total_recharge  DECIMAL(12,4) NOT NULL DEFAULT 0,
  total_consumed  DECIMAL(12,4) NOT NULL DEFAULT 0,
  updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (merchant_id) REFERENCES merchant(id)
);

-- ========================================
-- 7. merchant_transaction — 交易流水表
-- ========================================
CREATE TABLE merchant_transaction (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  merchant_id     VARCHAR(64)  NOT NULL,
  type            ENUM('recharge','consume','refund','freeze','unfreeze') NOT NULL,
  amount          DECIMAL(12,4) NOT NULL,
  balance_after   DECIMAL(12,4) NOT NULL,
  related_usage_id BIGINT,
  description     VARCHAR(256),
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_merchant_created (merchant_id, created_at),
  FOREIGN KEY (merchant_id) REFERENCES merchant(id)
);

-- ========================================
-- 8. session — 用户会话表
-- ========================================
CREATE TABLE session (
  id              VARCHAR(64)  PRIMARY KEY,
  skill_id        VARCHAR(64),
  merchant_id     VARCHAR(64)  NOT NULL,
  user_id         VARCHAR(64),
  channel         VARCHAR(32) DEFAULT 'web',
  status          ENUM('active','closed','timeout') DEFAULT 'active',
  message_count   INT DEFAULT 0,
  started_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  ended_at        DATETIME
);

-- ========================================
-- 9. message — 消息表
-- ========================================
CREATE TABLE message (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id      VARCHAR(64)  NOT NULL,
  role            ENUM('system','user','assistant','tool') NOT NULL,
  content         TEXT,
  metadata        JSON,
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_session_created (session_id, created_at),
  FOREIGN KEY (session_id) REFERENCES session(id)
);

-- ========================================
-- 10. skill_rate_limit — 限流规则表
-- ========================================
CREATE TABLE skill_rate_limit (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  skill_id        VARCHAR(64)  NOT NULL,
  limit_type      ENUM('rpm','tpm','concurrent') NOT NULL,
  limit_value     INT NOT NULL,
  time_window_sec INT DEFAULT 60,
  FOREIGN KEY (skill_id) REFERENCES skill(id)
);

-- ========================================
-- 11. audit_log — 审计日志表
-- ========================================
CREATE TABLE audit_log (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  operator_type ENUM('platform_admin','merchant','system') NOT NULL,
  operator_id   VARCHAR(64),
  action        VARCHAR(64) NOT NULL,
  target_type   VARCHAR(32),
  target_id     VARCHAR(64),
  detail        JSON,
  ip_address    VARCHAR(64),
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_target (target_type, target_id),
  INDEX idx_created (created_at)
);
```

### 2.3 双库同步说明

`skill` 和 `merchant_agent_binding` 存在于两个地方：

| | 平台数据库 | 运行时 MySQL |
|---|---|---|
| 用途 | 计费、展示、审计、路由 | 实时调度执行 |
| 读写方 | 平台自己读写 | 运行时自己读写 |
| 同步方式 | 平台调运行时管理 API → 运行时写入本地 MySQL + 更新缓存 |

`chat_history` 仅存在于运行时 MySQL，用于对话上下文持久化。

**关键**：
- **Skill 模式**的绑定：必须通过运行时的管理 API 执行，确保两边数据一致
- **Endpoint 模式**的绑定：只需写入平台数据库，运行时不需要知道（平台网关直接路由）

### 2.4 ER 关系图

```
【平台数据库】

   │                    └── agent_endpoint 有值 → Endpoint 模式 → 转发到定制智能体
   │
   ├──1:1── merchant_balance
   ├──1:N── merchant_transaction

       ──1:N── skill_pricing

【运行时本地 SQLite】

```

## 三、完整调用流程

### 3.1 Skill 注册流程

```
管理员在平台后台填写 Skill 定义
    │
    ▼
平台后端调用 POST http://runtime:3000/api/platform/skills
    │
    ▼
运行时写入本地 SQLite (skill 表) + 更新内存缓存
    │
    ▼ （同时）
平台后端写入自己的 skill 表（用于计费/展示）
```

### 3.2 商家绑定流程

**Skill 模式绑定**：

```
管理员选择商家 + Skill + 可选覆盖配置
    │
    ▼
平台后端调用 POST http://runtime:3000/api/platform/bindings
    { merchant_id, skill_id, persona_override, ... }
    │
    ▼
运行时写入本地 SQLite + 更新缓存
    │
    ▼ （同时）
平台后端写入自己的 merchant_agent_binding 表
```

**Endpoint 模式绑定**：

```
管理员选择商家 + 填写定制智能体地址
    │
    ▼
平台后端直接写入 merchant_agent_binding 表
    { merchant_id, agent_endpoint, agent_auth_header }
    │
    ▼
不需要通知运行时（网关直接路由到 endpoint）
```

```
 │                         │── 6.记录计量 ──────────────────────────────▶│
 │                         │── 7.计费扣款 ──────────────────────────────▶│
 │                         │── 8.持久化消息 ────────────────────────────▶│
 │                         │                        │                      │
 │◀── "您的订单已发货..." ─│                        │                      │
```

### 3.4 不同意图走不同分支（Skill 模式）

以客服型 Skill 为例，Workflow DAG 如下：

```
                    intent_classifier
                   /        |         \
            knowledge   tool_call      chat
                |           |           |
        knowledge_retrieval  tool_call  llm_chat (闲聊)
                |           |
            summarize    llm_chat (工具回复)
                |
            llm_chat (知识回复)
```

| 用户输入 | 意图 | 走哪条分支 | 执行的节点 |
|----------|------|-----------|-----------|
| "如何退货" | knowledge | knowledge 分支 | intent_classifier → knowledge_retrieval → summarize → llm_chat |
| "我的订单到哪了" | tool_call | tool_call 分支 | intent_classifier → tool_call → llm_chat |
| "你好" | chat | chat 分支 | intent_classifier → llm_chat |
| "我要找人工客服" | human_transfer | human_transfer 分支 | intent_classifier → human_transfer |

定制智能体只需遵守统一的请求/响应格式，平台网关即可透明转发。

```
POST /api/chat
```

```json
{
  "message": "用户消息",
  "merchant_id": "merchant_003",

```

**响应**（必须遵守的格式）：

```json
{
  "session_id": "sess_xxx",
  "merchant_id": "merchant_003",
  "response": "回复内容",
  "steps": [],
  "toolCalls": [],

  "fallback_used": false

```

### 5.2 建议实现的接口

| `POST` | `/api/chat/stream` | 流式对话（SSE） |
| `GET` | `/api/chat/history/:sessionId` | 会话历史 |

### 5.3 定制智能体可以用任何语言/框架

```python
# Python Flask 示例
@app.route('/api/chat', methods=['POST'])

        "response": response,
        "steps": [],
        "toolCalls": [],
        "retrieval_used": False,
        "fallback_used": False,
    }

    return {"status": "ok"}
```

## 六、Skill 配置包详解

### 6.1 完整结构

```json
{
  "skillId": "customer_service",
  "version": "1.0.0",

  "persona": {
    "name": "智能客服",
    "systemPrompt": "你是一个专业的客服助手，耐心解答用户问题...",
    "tone": "专业、友好",
    "instructions": ["不要编造信息", "工具失败时告知用户"]
  },

  "capabilities": {
    "tools": ["query_order", "query_product", "ticket_operation"],
    "knowledgeRetrieval": true,
    "collectionName": "default",
    "maxToolIterations": 5
  },

  "workflow": {
    "entry": "intent_classifier",
    "nodes": [
      {
        "id": "intent_classifier", "type": "intent_classifier", "name": "意图分类",
        "config": { "categories": ["knowledge", "tool_call", "chat"] },
        "ports": { "knowledge": "kp", "tool_call": "tp", "chat": "cp" }
      },
      { "id": "knowledge_retrieval", "type": "knowledge_retrieval", "name": "知识检索", "config": { "topK": 5 } },
      { "id": "summarize", "type": "summarize", "name": "知识总结", "config": { "topK": 3 } },
      { "id": "knowledge_chat", "type": "llm_chat", "name": "知识回复", "config": { "temperature": 0.5, "contextSources": ["summarize"] } },
      { "id": "tool_call", "type": "tool_call", "name": "工具调用", "config": {} },
      { "id": "tool_chat", "type": "llm_chat", "name": "工具回复", "config": { "temperature": 0.3, "contextSources": ["tool_call"] } },
      { "id": "chat", "type": "llm_chat", "name": "闲聊回复", "config": { "temperature": 0.7 } }
    ],
    "edges": [
      { "source": "intent_classifier", "target": "knowledge_retrieval", "sourcePort": "knowledge" },
      { "source": "intent_classifier", "target": "tool_call", "sourcePort": "tool_call" },
      { "source": "intent_classifier", "target": "chat", "sourcePort": "chat" },
      { "source": "knowledge_retrieval", "target": "summarize" },
      { "source": "summarize", "target": "knowledge_chat" },
      { "source": "tool_call", "target": "tool_chat" }
    ]
  },

  "config": {
    "maxIterations": 5,
    "toolTimeoutMs": 10000,
    "toolMaxRetries": 3,
    "contextWindowSize": 20,
    "temperature": 0.7
  }
}
```

### 6.2 可用的节点类型（13 种）

| NodeType | 说明 | 需要的外部依赖 | 典型用途 |
|----------|------|---------------|---------|
| `intent_classifier` | 意图分类，输出 selectedPort 决定分支 | LLM | Workflow 入口节点 |
| `knowledge_retrieval` | 知识检索 | 知识库服务 | FAQ、文档查询 |
| `tool_call` | 工具调用（直接调用 / Function Calling） | 已注册工具 | 查订单、查商品 |
| `llm_chat` | LLM 对话，生成自然语言回复 | LLM | 最终回复节点 |
| `summarize` | 知识总结，提炼检索结果 | LLM | 检索后压缩上下文 |
| `rerank` | 重排序，对检索结果二次排序 | LLM（可选） | 提升检索精度 |
| `condition` | 条件分支，走 true/false 路径 | 无 | 置信度检查、空结果判断 |
| `human_transfer` | 转人工，标记需要人工客服 | 无 | 用户要求转人工 |
| `parallel` | 并行执行多个子任务 | 子任务依赖 | 同时检索多个知识库 |
| `loop` | 循环执行子任务直到满足条件 | 子任务依赖 | 分页查询、重试 |
| `webhook` | 调用外部 HTTP API | 外部服务 | 调用商家自有 API |
| `template_response` | 模板回复，变量替换 | 无 | 欢迎语、固定提示 |
| `custom` | 自定义，动态加载外部代码 | 外部脚本 | 商家专属逻辑 |

### 6.3 商家覆盖机制

绑定商家时可通过 override 覆盖 Skill 默认值，实现同 Skill 不同商家的个性化：

```json
{
  "merchant_id": "merchant_001",
  "skill_id": "customer_service",
  "persona_override": {
    "name": "XX数码客服",
    "systemPrompt": "你是XX数码旗舰店的客服，主营手机和电脑..."
  },
  "capabilities_override": {
    "collectionName": "merchant_001_products"
  },
  "config_override": {
    "temperature": 0.4
  },
  "enabled": true
}
```

合并逻辑：`最终配置 = Skill 默认值 + override（覆盖同名字段）`

## 七、你需要开发的平台功能

### 7.1 API 网关（核心，参考 1.4 的伪代码）

你的网关负责：接收用户请求 → 查路由表 → 前置校验 → 转发目标 → 后置计费 → 返回用户。

关键路由逻辑：
1. 查 `merchant_agent_binding` 表
2. 有 `agent_endpoint` → 直接转发到定制智能体
3. 无 `agent_endpoint` → 转发到通用运行时
4. 计费/计量/持久化对所有模式统一处理

### 7.2 Skill 管理后台

| 功能 | 调用的运行时 API | 说明 |
|------|-----------------|------|
| 注册新 Skill | `POST /api/platform/skills` | 填写 persona/capabilities/workflow/config |
| 查看所有 Skill | `GET /api/platform/skills` | 列表展示 |
| 删除 Skill | `DELETE /api/platform/skills/:skillId` | 软删除 |
| 绑定商家（Skill 模式） | `POST /api/platform/bindings` | 传 `skill_id` |
| 绑定商家（Endpoint 模式） | 直接写平台数据库 | 传 `agent_endpoint` |
| 查看绑定 | `GET /api/platform/bindings` + 平台数据库 | 合并展示 |
| 解绑 | `DELETE /api/platform/bindings/:merchantId` | Skill 模式调 API，Endpoint 模式删数据库 |
| 启用/禁用 | `PATCH /api/platform/bindings/:merchantId` | 传 `enabled: true/false` |
| 刷新缓存 | `POST /api/platform/cache/reload` | 从数据库重新加载 |

你负责开发，与运行时无关：

- 用量统计/账单
- 限流配置
- 审计日志查看

## 十、数据流转全景

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Skill 注册 & 商家绑定                             │
│                                                                         │
│  Skill 模式绑定：                                                        │
│  管理后台 → POST /api/platform/bindings { skill_id } → 运行时 SQLite    │
│  （同时）平台写入自己的 merchant_agent_binding 表                          │
│                                                                         │
│  Endpoint 模式绑定：                                                     │
│  管理后台 → 直接写入平台 merchant_agent_binding 表                        │
│  （不需要通知运行时）                                                     │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                           用户对话流程                                    │
│                                                                         │
│  用户 → 平台网关 → 查 merchant_agent_binding                             │
│                      │                                                  │
│                      ├── agent_endpoint 有值 → 转发到定制智能体           │
│                      │   定制智能体自行处理，返回统一格式响应               │
│                      │                                                  │
│                      └── agent_endpoint 为空 → 转发到通用运行时           │
│                          运行时 SkillDispatcher.resolve()                │
│                          → 查缓存/DB → 合并 override → ResolvedSkill     │
│                          → WorkflowEngine.execute()                      │
│                          → 返回响应                                      │
│                                                                         │
│  平台后置处理（统一，不区分模式）：                                        │
│  → 记录 skill_usage                                                     │
│  → 计费 → UPDATE merchant_balance                                       │
│  → INSERT merchant_transaction                                          │
│  → INSERT message (user + assistant)                                    │
└─────────────────────────────────────────────────────────────────────────┘
```
