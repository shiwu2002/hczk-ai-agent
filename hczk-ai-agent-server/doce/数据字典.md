# 桓宸智科AI平台 - 数据字典

## 一、用户相关

### users（用户表）
| 字段 | 类型 | 含义 | 业务规则 |
|------|------|------|----------|
| id | BIGINT | 主键ID | 自增，内部使用 |
| user_id | VARCHAR(32) | 用户唯一标识 | 注册时随机生成（U+16位大写字母数字），全局唯一，对外展示 |
| username | VARCHAR(50) | 登录账号 | 全局唯一，支持字母/数字/下划线 |
| password | VARCHAR(255) | 登录密码 | BCrypt加密存储，不可逆向解密 |
| email | VARCHAR(100) | 邮箱 | 全局唯一，用于通知和找回密码 |
| phone_number | VARCHAR(20) | 手机号 | 可选，用于短信通知 |
| company_name | VARCHAR(100) | 公司名称 | 可选，企业用户填写 |
| role | TINYINT | 角色 | 0=管理员(ADMIN)，1=普通用户(USER) |
| balance | DECIMAL(19,4) | 账户余额 | 单位：人民币元，精确到分 |
| total_usage_tokens | BIGINT | 累计消耗token | 统计用户所有调用的token总数 |
| status | TINYINT | 账户状态 | 0=正常(active)，1=禁用(inactive) |
| deleted | TINYINT | 逻辑删除 | 0=未删除，1=已删除 |
| created_at | DATETIME | 创建时间 | 自动填充 |
| updated_at | DATETIME | 更新时间 | 自动填充 |

## 二、模型相关

### ai_models（AI模型表）
| 字段 | 类型 | 含义 | 业务规则 |
|------|------|------|----------|
| id | BIGINT | 主键ID | 自增 |
| name | VARCHAR(100) | 显示名称 | 如"DeepSeek-V3" |
| provider | VARCHAR(100) | 提供商 | 如"百度智能云"、"阿里云" |
| provider_type | VARCHAR(50) | 接口类型 | OPENAI_COMPATIBLE / ANTHROPIC / MODELSCOPE |
| model_id | VARCHAR(100) | 调用标识 | API调用时的model参数值，全局唯一 |
| status | TINYINT | 服务状态 | 0=启用(ACTIVE)，1=停用(INACTIVE) |
| api_base | VARCHAR(255) | 基础地址 | 兼容OpenAI格式的API地址 |
| api_key | VARCHAR(512) | 平台密钥 | 管理员配置的厂商API Key |
| max_tokens | INT | 最大上下文 | 模型支持的最大token数 |
| thinking | BOOLEAN | 深度思考 | 是否启用enable_thinking |
| created_at | DATETIME | 创建时间 | 自动填充 |
| updated_at | DATETIME | 更新时间 | 自动填充 |

> **定价说明**：模型不再设置定价（已移除input_price/output_price字段），计费由API Key的`unit_price`字段统一管理，详见"四、API Key相关"。

|------|------|------|----------|

| status | TINYINT | 运行状态 | 0=启用(ACTIVE)，1=停用(INACTIVE) |
| agent_type | VARCHAR(50) | 类型 | MODEL / SKILL / ENDPOINT，见下方类型说明 |
| skill_id | VARCHAR(100) | Skill ID | SKILL类型必填 |
| endpoint | VARCHAR(255) | 外部地址 | ENDPOINT类型必填 |
| endpoint_auth_header | VARCHAR(255) | 认证头 | ENDPOINT类型的鉴权信息 |
| total_calls | BIGINT | 调用次数 | 累计被调用的次数 |
| total_tokens | BIGINT | Token消耗 | 累计消耗的token总数 |
| avg_latency | INT | 平均延迟 | 单位：毫秒(ms) |

| updated_at | DATETIME | 更新时间 | 自动填充 |

**智能体类型**：
| 类型值 | 中文名 | 必填字段 | 适用场景 |
|--------|--------|----------|----------|
| MODEL | 模型型 | model_id | 直接绑定大模型对话 |
| SKILL | 技能包型 | skill_id | 绑定Skill配置包，走通用运行时 |
| ENDPOINT | 端点型 | endpoint | 转发到外部定制智能体 |

## 四、API Key相关

### api_keys（API密钥表）
| 字段 | 类型 | 含义 | 业务规则 |
|------|------|------|----------|
| id | BIGINT | 主键ID | 自增 |
| name | VARCHAR(100) | 密钥名称 | 用户自定义，如"生产环境" |
| api_key | VARCHAR(512) | 密钥值 | 格式：sk-hczk-xxxx，全局唯一 |
| user_id | BIGINT | 所属用户 | **每个用户仅允许一个API Key**（user_id唯一约束） |
| model_ids | JSON | 绑定模型 | 绑定的大模型ID列表，一个Key可绑定多个模型 |
| unit_price | DECIMAL(19,6) | 统一Token单价 | 元/千Tokens，所有绑定模型统一计费 |
| total_calls | BIGINT | 调用次数 | 该Key的累计调用次数 |
| total_input_tokens | BIGINT | 累计输入Token | 该Key的累计输入Token数量 |
| total_output_tokens | BIGINT | 累计输出Token | 该Key的累计输出Token数量 |
| total_cost | DECIMAL(19,6) | 累计费用 | 该Key的累计消耗费用(元) |
| status | TINYINT | 密钥状态 | 0=可用(active)，1=禁用(inactive) |
| last_used_at | DATETIME | 最后使用 | 记录最近一次调用时间 |
| created_at | DATETIME | 创建时间 | 自动填充 |

**API Key格式**：`sk-hczk-` + 24位随机字母数字组合

**唯一性约束**：
- `api_key`：密钥串全局唯一
- `user_id`：每个用户只能拥有一个API Key

## 六、计费相关

### billing_records（计费记录表）
| 字段 | 类型 | 含义 | 业务规则 |
|------|------|------|----------|
| id | BIGINT | 主键ID | 自增 |
| user_id | BIGINT | 用户ID | 关联users.id |
| api_key_id | BIGINT | API Key ID | 关联api_keys.id，记录通过哪个Key调用 |
| model_id | BIGINT | 调用模型ID | 记录本次调用的是哪个模型 |
| type | VARCHAR(20) | 记录类型 | TOKEN_USAGE=消耗扣费，RECHARGE=充值 |
| amount | DECIMAL(19,4) | 金额 | 正数=充值，负数=消费 |
| balance_after | DECIMAL(19,4) | 操作后余额 | 记录操作后的账户余额 |
| input_tokens | BIGINT | 输入token | 仅TOKEN_USAGE类型有值 |
| output_tokens | BIGINT | 输出token | 仅TOKEN_USAGE类型有值 |
| detail | VARCHAR(500) | 详情 | 如"API Key调用模型[DeepSeek-V3] - 输入:50 tokens, 输出:250 tokens, 单价:0.002元/千Tokens" |
| created_at | DATETIME | 创建时间 | 自动填充 |

**计费公式**：
```
费用 = (input_tokens + output_tokens) / 1000 × unit_price
```
- `unit_price` 来自 API Key 的 `unit_price` 字段
- 输入和输出Token使用相同单价计费
- 费用精确到小数点后6位，四舍五入

**Token 估算规则**（流式响应无法获取精确 usage，采用字符估算）：
- 综合混合文本：约 2 字符 = 1 token
- 估算工具类：`com.hczk.hczkaiagentserver.util.TokenCounter`

**计费流程**：
1. API Key认证 → 查询API Key信息（unitPrice、modelIds）
2. 验证模型在API Key绑定范围内
3. 余额预检查
4. 调用模型流式输出
5. 估算Token → 按API Key的unitPrice计算费用
6. 扣减余额 → 记录账单 → 更新API Key统计

### recharge_records（充值记录表）

| created_at | DATETIME | 创建时间 | 自动填充 |

**充值套餐规则**：

## 八、枚举值速查表

| 枚举名 | Java类 | 数据库值 | 说明 |
|--------|--------|----------|------|
| role | UserRole | 0 / 1 | 0=管理员(ADMIN)，1=普通用户(USER) |
| model_status | ModelStatus | 0 / 1 | 0=启用(ACTIVE)，1=停用(INACTIVE) |
| agent_status | AgentStatus | 0 / 1 | 0=启用(ACTIVE)，1=停用(INACTIVE) |
| apikey_status | - | 0 / 1 | 0=可用(active)，1=禁用(inactive) |
| user_status | - | 0 / 1 | 0=正常(active)，1=禁用(inactive) |
| user_deleted | - | 0 / 1 | 0=未删除，1=已删除 |
| provider_type | ModelProviderType | OPENAI_COMPATIBLE / ANTHROPIC / MODELSCOPE | 模型接口类型 |
| platform_type | PlatformType | MEITUAN / DOUYIN | 对接平台 |
| billing_type | BillingType | TOKEN_USAGE / RECHARGE | 计费类型 |

| agent_type | - | MODEL / SKILL / ENDPOINT | 智能体类型 |

> **枚举序列化说明**：所有枚举字段在JSON API中均使用数据库存储值（Integer/String），通过`@JsonValue`注解实现。例如`ModelStatus.ACTIVE`序列化为`0`，`ModelProviderType.OPENAI_COMPATIBLE`序列化为`"OPENAI_COMPATIBLE"`。
